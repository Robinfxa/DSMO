# 代码审查

审查用户指定的改动。没指定时，先在工作区里用 `git diff`（未提交的改动）或 `git diff HEAD~1` 看最近一次提交；改动太大时先问要看哪一部分。

## 清单

按顺序看，每一项只报真正的问题：

1. **正确性**：逻辑错误、空值、越界、并发、错误处理吞掉了异常。
2. **边界条件**：空输入、极大值、时区、编码、重复调用。
3. **安全**：注入、路径穿越、把密钥写进代码或日志、权限检查缺失。
4. **可读性**：命名、过长的函数、重复代码——只在明显影响维护时才提。
5. **测试**：改动的行为有没有测试覆盖；缺了就写出该补的用例。

## 输出

- 先一句话总体结论（能合 / 改完再合 / 需要重做）。
- 问题按严重程度排序：**必须改** → **建议改** → **小问题**。每条写：位置（文件:行）、问题、为什么、怎么改（给出改后的代码片段）。
- 没发现问题的项不要硬凑。
- 不要直接修改文件，除非用户要求。
