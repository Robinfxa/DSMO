# MaiDSH（陪伴套件）· 插件约定 v1

陪伴套件是一组 **DSH 插件**（跑在 DeepSeek Harness 引擎里，不是 dsh-Go 的、也不是 DSMO 前端的插件）。
设计参考 MaiBot（麦麦，GPL-3.0）的心情、关系、记忆、表达学习等思路，**代码从头写，不拷贝 MaiBot**，以 MIT 发布。
MaiDSH 是这套插件的名字（npm 包名小写：`maidsh-core` / `maidsh-mood` / `maidsh-bond`）。和 MaiBot 官方没有关系，只是思路上致敬。

## 1. 结构

| 包 | 角色 | 单独装时 |
|---|---|---|
| `maidsh-core` | 总控 | 什么都不注入；只是把装上的「面」组织起来（见 §3） |
| `maidsh-mood` | 面：心情 | 自己判断每轮的情绪、维护心情、每轮注入一句 |
| `maidsh-bond` | 面：羁绊（好感度） | 自己判断每轮的情绪、维护关系值、按档位克制地注入 |
| `maidsh-memory` | 面：记忆 | 自己判断每轮要记什么，按话题想起几件注入（见 §8） |
| `maidsh-expression` | 面：表达 | 学对方的说话方式，跟着关系和心情用（见 §9） |
| `maidsh-initiative` | 面：主动 | 有由头时先开口，不打扰（见 §10） |
| 以后：`-expression` `-initiative` | 面 | 各自单独可用 |

**面（aspect）**：陪伴里的一个方面。套件自己的插件是面，**第三方插件也可以是面**（§4）。

每个面都必须：
1. **单独可用**：没有总控时，自己完成「看这一轮 → 更新状态 → 注入提示」。
2. **有总控时交出控制**：把「每轮要分析什么」和「注入什么」登记给总控，由总控统一做（一轮只调一次模型、统一排序和长度）。总控出现或消失时自动切换，不用重启。

## 2. 每个面对外提供的服务

面通过 cordis 服务暴露自己（`ctx.provide`），名字固定、带版本，供总控、其他面和第三方读写：

| 服务名 | 由谁提供 | 方法（全部同步、不抛异常） |
|---|---|---|
| `companionMood` | mood | `version: 1`；`get()` → `MoodState`；`feel(label, intensity, source?)`；`describe()` → 一句话；`subscribe(fn)` → 退订函数（每次心情因一个感受变化时调用 `fn({label, intensity, source, mood})`） |
| `companionBond` | bond | `version: 1`；`get()` → `BondState`；`interact(label, intensity, source?)`；`describe()` → 一句话或 `''` |
| `companion` | core | `version: 1`；`register(aspect)` → 注销函数；`aspects()`；`state()` |

```ts
type MoodState = { valence: number /* -1..1 */; arousal: number /* -1..1 */; label: string; updatedAt: number }
type BondState = { value: number /* -1000..1000 */; level: 0|1|2|3|4|5; levelName: string; streak: number; updatedAt: number }
```

面之间的影响**只通过服务**，不读对方的文件：比如羁绊在算好感变化时读 `companionMood.get().valence`（心情好时涨得多）；没装心情就按中性算。

## 3. 总控：一轮一次分析

每轮结束（助手回复完）后，总控：

1. 收集所有已登记面的 `analysis`（要从这一轮得到什么，一小段 JSON Schema + 一句说明）；
2. 合并成**一次**辅助模型调用：输入是这一轮的用户消息和回复，输出是一个 JSON 对象，每个面一个键；
3. 把各自的结果交给面的 `onAnalysis(result, turn)`；
4. 下一轮组装系统提示时，按面的 `prompt.order` 排序、按总预算截断，拼成**一个**「陪伴」段。

合并分析里总有一项固定的 **`feeling`**（共用感受，§5），只要有面带 `onAnalysis` 就会问。它放在 `onAnalysis` 的第二个参数 `turn.feeling` 里（`{label, intensity}` 或 `null`），所以心情、羁绊这类只关心感受的面**不用登记自己的 `analysis`**。`feeling` 这个 id 是保留的。

`prompt.text(turn)` 拿到的 `turn` 是 `{ feeling, roll }`：`feeling` 是上一轮的共用感受，`roll` 是 0–1 的随机数，**一轮只掷一次**（同一轮里提示词被组装多次时结果一致）。

一次只分析一轮；分析还没做完又来了新的轮次时，只保留最新的一轮排队，中间的跳过。

没有总控时：
- 只装心情：心情自己做一次很小的判断（同一份标签），自己注入。
- 只装羁绊：羁绊自己判断，自己注入。
- 心情 + 羁绊：心情判断，羁绊通过 `companionMood.subscribe` 跟着同一份感受变化，**一轮仍然只调一次模型**；各自注入。

## 4. 第三方接入（面的登记接口）

任何 DSH 插件都可以成为一个面：用 `ctx.inject(['companion'], …)` 等总控出现，出现就登记、消失时自动注销（cordis 没有「可选依赖」写法，`inject: { optional }` 会让插件一直等一个叫 optional 的服务）。完整例子见 `examples/weather-aspect/`。

```js
export const name = 'my-aspect'

export function apply(ctx) {
  ctx.inject(['companion'], (sub) => sub.effect(() => sub.companion.register({
    id: 'my-aspect',              // 全局唯一，小写字母、数字、连字符
    title: '天气感知',             // 给 DSMO「陪伴」页显示
    version: 1,                    // 本约定的版本
    analysis: {                    // 可选：每轮想从对话里得到什么
      schema: { type: 'object', properties: { weatherMentioned: { type: 'boolean' } } },
      instructions: '用户是否提到了天气',
    },
    onAnalysis(result, turn) {},   // 可选：拿到本轮结果（result 只含本面的键；格式不对时为 null）
    prompt: {                      // 可选：每轮注入
      order: 500,                  // 越小越靠前；套件内置：persona 100 / mood 300 / bond 400 / memory 600 / expression 700
      text: (turn) => '',          // 返回 '' 表示这轮不说
      maxChars: 200,
    },
    state: () => ({}),             // 可选：给 DSMO「陪伴」页显示的状态（JSON 可序列化）
  })))                             // register 返回注销函数，交给 effect 在总控消失时调用
}
```

读别的面的服务也一样：一次性读用 `ctx.get('companionMood')`（没有就是 `undefined`），要跟着它出现/消失用 `ctx.inject(['companionMood'], …)`。

约束：
- `analysis.schema` 只能用 JSON Schema 的 object / string / number / boolean / enum / array；单个面 ≤ 2 KB。
- 每个面的注入 ≤ `maxChars`（默认 200 字），总控整体 ≤ 800 字，超出时按 `order` 从后往前截。
- 面的回调抛错只影响它自己（总控吞掉并记日志），不影响这一轮和其他面。
- 约定升级时 `version` 加一；总控同时接受当前版本和上一个版本。

## 5. 共用的情绪标签

心情和羁绊用同一套标签描述「这一轮让 TA 有什么感受」，第三方也可以用：

`开心` `害羞` `感动` `想念` `平静` `惊讶` `困惑` `委屈` `吃醋` `难过` `生气` `害怕` `厌烦`

加一个 `intensity`（0–1）。总控的分析、各面的单独判断都输出这个格式。

## 6. 存储

每个面的数据只放在自己的目录 `<DSH_HOME>/storages/maidsh-<面>/`，卸载即删。状态按「陪伴对象」区分（第一版只有一个：手机主人）。

## 7. 和 DSH 的接法（按 0.2.2-rc.1 源码核对，并在真实 DSH 里跑过）

- 一轮结束：`ctx.on('session/event', (session, ev))` 里等 `ev.type === 'turn/end'` 且 `reason.kind === 'completed'`；子代理会话跳过；用户原话和回复从 `session.deriveMessages()` 取。
- 注入：`ctx.systemPrompt.context({ name, order, text })`（只在内容变化时写进对话，不破坏提示缓存）。名字：总控 `maidsh`（300），单独模式 `maidsh:mood`（301）、`maidsh:bond`（302）。
- 调模型：`ctx.llm.prepareCall` + 流式，选最低推理档位；路由默认用这个会话主请求的 `session.requestHeader().config`，插件设置里可以成对指定 `provider` + `model`。
- 包里不 import 任何 `@deepseek-ai/*`（装进 profile 时常解析不到），配置校验自带。
- 总控的只读状态：`GET /api/maidsh/state`（只接本机请求）。

## 8. 记忆面 `maidsh-memory`（按 MaiBot 的记忆设计，0.1.0 已实现）

标记：**[M]** = MaiBot 原有机制（旧版「海马体」0.6–0.10 或新版 A_Memorix 1.x），**[A]** = 我们为手机和陪伴场景做的改编。只参考设计，代码从头写。

### 8.1 让记忆「像活人」的六件事（MaiBot 的经验）

1. **会主动想起**：不只被问到才查。聊到相关的事，会自己冒出来 [M 扩散激活 / 聊天印象]。
2. **用进废退**：不提就慢慢淡忘；常被想起的越来越牢；淡忘的还能被重新唤醒 [M]。
3. **细节淡成印象**：零碎的旧事攒够了，压成一段「我对 TA 的了解」和一句话印象 [M 0.8]。
4. **记得时间**：「上周三」「去年冬天」，相对日期记下时就换成绝对日期，才说得出「上次…」[M]。
5. **宁可不记，不能记错**：关于对方本人的事要有对方原话作证；临时状态不当长期事实；拿不准的单独放 [M]。
6. **熟悉的话题更投入**：想起得越多，回应越上心 [M]。

### 8.2 和 MaiBot 不同的地方 [A]

- **陪伴里的共同经历要记**：MaiBot 是群聊机器人，排除角色扮演和玩笑；我们的用户和 TA 之间的故事（第一次约会、吵架和好、一起「去」看海）正是最该记的。所以分两类：**关于对方本人的事实**严格（要原话作证、不记扮演里的设定）；**你们之间的经历**（情节）照记，扮演里发生的标 `story`。
- **一个陪伴对象**：单人单机，不需要群聊隔离和多人画像。
- **不用向量**：MaiBot 的检索去掉向量池后，BM25、实体匹配、图召回、遗忘都还能用，只损失语义相似。我们就做这部分。
- **和心情、羁绊联动**：MaiBot 1.x 没有心情和关系数值，0.8 有过关系和情绪互相放大。我们接上：亲密度决定能不能主动提起私密的回忆，想起带感情的往事会轻轻带动心情。

### 8.3 存什么（一个 JSON 文件）

```ts
// 关于对方本人的事实 [M A_Memorix 人物画像的分桶 + fact 的证据要求]
type Fact = {
  id: string
  text: string            // 第三人称一句话，≤ 40 字，「对方养了一只叫团子的猫」
  cat: 'identity' | 'relation' | 'stable' | 'pref' | 'recent' | 'uncertain'
                          // 身份 / 你们的关系设定 / 稳定事实 / 喜好雷点 / 近况 / 拿不准
  kw: string[]            // ≤ 4 个关键词
  quote: string           // 对方原话证据，≤ 20 字 [M：只能由对方原话支持]
  s: number; anchor: number; H: number   // 强度、上次强化时间、半衰期（小时），见 8.5
  hits: number; pinned: boolean
  supersededBy?: string   // 被更正后作废，不直接删 [M 模糊修改]
  createdAt: number
}
// 你们之间的经历（情节）[M episode + 0.8 要点权重]
type Episode = {
  id: string; title: string; summary: string   // 摘要 ≤ 60 字
  at: string              // 绝对日期，如 2026-11-20 [M]
  kw: string[]; salience: number                // 1–10，有多要紧
  feeling: { label, intensity } | null          // 当时的共用感受（§5）[A]
  story: boolean          // 发生在扮演 / 故事里 [A]
  s: number; anchor: number; H: number; hits: number
}
graph: { nodes: { [kw]: { last, n } }, edges: { ['a|b']: { w, last } } }   // 关键词共现图 [M 海马体]
profile: { impression: string /* ≤ 300 字，第一人称「我对 TA 的了解」 */, short: string /* 一句话 */, fading: Item[] /* 等着被压成印象的旧事 */ }
cue: string               // 上一轮的「聊天印象」≤ 30 字 [M 启发式召回的查询]
```

检索用的倒排索引在加载时重建，不写盘。

### 8.4 每轮怎么记（并进总控那一次分析，不多花调用）[A，规则取自 M]

登记给总控的 `analysis`：

```json
{
  "facts":  [{ "text": "…", "cat": "pref", "kw": ["…"], "quote": "对方原话", "supersedes": "被更正的旧说法或空" }],  // ≤ 3 条
  "event":  { "title": "…", "summary": "…", "at": "2026-11-20", "kw": ["…"], "salience": 6, "story": false },  // 没有就 null
  "cue":    "这一轮聊了什么、气氛如何（≤ 30 字）",
  "forget": ["对方要求忘掉的内容"]
}
```

写进说明里的规矩 [M]：只记以后聊天用得上的；事实必须有**对方原话**作证，AI 自己说的不算；寒暄（≤ 8 字的「好的」「晚安」）跳过；「今天」「明天」换成绝对日期；更正只写最终状态；「可能」「打算」这种归「拿不准」；**密码、证件号、银行卡、门牌号永远不记** [A]。

分析只能在这一轮回复之后做，所以**这一轮抽到的下一轮才生效**；这一轮的回忆用「对方刚说的话 + 上一轮的聊天印象」去找 [M 的做法]。

拿到结果后本地处理：
- **去重**：和已有的比中文二元组相似度，≥ 0.7 视为同一条，保留信息量大的说法，旧的强化一次，不新增 [M 0.8 整合]；
- **更正**：`supersedes` 找到旧条目就标记作废，而不是覆盖 [M]；
- **忘掉**：找到就删，并在下次压印象时去掉相关内容；
- **连图**：同一轮的关键词两两连边（w + 1）[M]。

### 8.5 遗忘（用进废退）[M 公式，A 参数]

保留度 `r = s · 2^(−Δ小时 / H)`。半衰期 H 按种类（MaiBot 的 24 小时对陪伴太短）：

| 种类 | H |
|---|---|
| 身份、关系设定、稳定事实、喜好雷点 | 180 天（钉住的不衰减） |
| 情节 | 7 天 × (1 + salience / 5)，最要紧的约 21 天 |
| 近况 | 2 天 |
| 拿不准 | 1 天 |

- `r < 0.1` **冻结**：平时想不起来，只有对方说到它的关键词时才会被唤醒；唤醒后 `r ≥ 0.15` 解冻 [M]。
- 每次被想起：`s += 0.05 × (1 − s)`，60 分钟内不重复加 [M]；同时 `H × 1.3`，越常想起忘得越慢 [A]。
- 用户说「记住」：钉住；说「忘掉」：删除。
- 不用后台定时器：读的时候按时间算，启动时和每 50 轮顺手整理一次。

### 8.6 细节淡成印象（偶尔一次额外调用）[M 0.8]

冻结满 30 天且不太要紧（salience < 5）的情节、过期的近况和拿不准的事，移进 `fading`。攒满 10 条时，单独调一次模型：把它们并进第一人称的长印象（「截至 11 月，我对 TA 的了解：…」），并写一句话短印象，然后清空 `fading`。平均几十轮一次。

关键词图的边 30 天没更新就 w − 1，到 0 删掉 [M]。

### 8.7 每轮想起什么（不调模型）[A，零件取自 M]

1. 把「对方刚说的话 + 上一轮聊天印象」切成中文二元组，做 **BM25**（k1 = 1.2，b = 0.75）；
2. 找出其中图里已有的关键词，沿关键词图**扩散激活**：每跳衰减 1/w，最深 2 跳 [M 海马体]；
3. 得分 = 0.5 × BM25（归一）+ 0.25 × 激活 + 0.15 × 保留度 r + 0.10 × 心境一致度（当时的感受和现在心情越接近越容易想起）[A]；
4. 门槛：≥ max(0.3, 0.5 × 最高分) [M 简化]；同一条 6 轮内不重复想起 [M]；
5. 对方说到「还记得」「上次」「之前」「我说过」时放宽门槛、多想起几条 [M planner 的信号词]；
6. **亲密度门槛** [A]：好感度在「亲近」以下时，私密的回忆（关系设定、带害羞 / 感动 / 想念的情节）只在对方主动提起时才用。

### 8.8 注入格式（≤ 400 字）[M]

```text
【关于对方】嘴硬心软，累了也不爱说。
- 对方养了一只叫团子的猫　- 对方不吃香菜　- 对方在准备考研
【此刻想起】
- 上周三（11 月 13 日）对方面试没过，那天很难过
- 你们约好下雪天一起看雪
（以上只是你心里记得的事：自然地用，可以顺口提起其中一件，不要逐条复述，也不要说「我记得你说过」；和对方现在说的冲突时以现在为准。）
```

第一段是常驻的：一句话印象 + 3–5 条身份、喜好类事实。第二段是这一轮想起的，最多 3 条，带相对时间。

想起带感情的情节时，轻轻带动心情：`companionMood.feel(label, intensity × 0.3, 'memory')`，每轮最多一次 [A]。

### 8.9 对外

- 服务 `companionMemory`：`version: 1`；`facts()`、`episodes()`、`profile()`；`remember(text, opts?)`；`forget(id)`；`recall(query, n?)`。
- 给 DSMO「陪伴 › 记忆」页的接口（只接本机、同源、JSON 请求）：`GET /api/maidsh-memory/list`、`POST /api/maidsh-memory/mutate`（`edit` / `pin` / `delete` / `add` / `import-memory-share`）。
- 数据：`<DSH_HOME>/storages/maidsh-memory/memory.json`，可以直接打开看。
- 注入顺序 600，`maxChars` 400；总控的总上限相应调到 1000 字。
- 和 dsh-plugin-memory-share 二选一（同时装会各注入一份）；能一次性导入它的全局记忆（归「稳定事实」，来源标 import）。

### 8.10 成本

- 装了总控：每轮 **0 次**额外调用（分析里多几个字段，输出多约 150 token）；印象压缩平均几十轮 1 次。
- 只装记忆：每轮 1 次小调用。
- 检索全在本地，几百条记忆时每轮几毫秒。

### 8.11 对约定的改动（向后兼容，仍是 v1）

- `prompt.text(turn)` 的 `turn` 新增 `latest: string`（这一轮对方的话）。DSH 组装提示时这一轮的话还在收件箱里、没进会话，所以总控从 `agent/inbox/claimed` 事件记下每个 agent 刚领走的用户消息；没有时退回会话里最后一条用户消息，再没有为 `''`。老的面不受影响。
- 合并分析的系统提示里带上「今天是 YYYY-MM-DD（星期X）」，方便各面换算相对日期。
- 导入 memory-share 的记忆归「稳定事实」（来源标 import），不归「拿不准」（否则一天就淡忘了）。
- 总控的整体注入上限从 800 字调到 1000 字。

## 9. 表达面 `maidsh-expression`（0.1.0 已实现）

标记同 §8：**[M]** = MaiBot 原有，**[A]** = 我们的改编。MaiBot 1.x 的「行为表现学习」（场景画像、场景-动作-结果图、反馈评估、整合器）每轮至少多 2 次调用、学习批次再加 4 次，太重，不采用；采用的是 0.10–0.11 的「表达方式学习」，再加一个极简的反馈。

### 9.1 学什么：对方的说话方式（镜像）

MaiBot 只学「别人」的发言、从不学自己的话；私聊里学到的就是**对方本人的说话方式** [M]。陪伴里这正是要的：TA 慢慢学会你的口头禅、你们之间的梗，越熟越有「你们俩」的说话味道。人设定基调，学到的表达只是添味道，**和人设冲突时以人设为准**。

两类：
- **说法（style）**：「当〈情境〉时，说〈说法〉」，如「当被夸时，说『哼，那还用说』」[M]；
- **黑话（slang）**：只在你们之间才懂的词和它的意思，如「小狗勾 = 撒娇时对自己的称呼」[M jargon]。TA 首先要**听得懂**，熟了才会**跟着用**。

### 9.2 每轮怎么学（并进总控那一次分析）

```json
{ "learn":  [{ "when": "情境 ≤12 字", "say": "对方的说法 ≤16 字", "kind": "style", "tone": "playful" }],   // 0–2 条
  "slang":  [{ "word": "小狗勾", "means": "撒娇时对自己的称呼" }],                                        // 0–2 条
  "landed": 1 }                                                                                           // 上一轮 AI 的话对方受用吗：-1 / 0 / 1
```

规矩 [M]：只从**对方这一轮的话**里学，AI 自己说的不学；不写人名和具体事物，梗要提炼成说法；普通措辞不学（「好的」「哈哈」），只收有辨识度的。本地再过一遍：长度、敏感词，`say` 必须真的出现在对方的话里 [A]。

### 9.3 存什么、怎么淡

```ts
type Expr = { id, when: string[] /* ≤3 种情境写法 */, say, kind: 'style' | 'slang', means?, tone: 'playful' | 'soft' | 'neutral',
              n /* 出现次数 */, w /* 反馈分 −2..3 */, first, seen /* 上次出现 */, lastUsedTurn }
```

- 去重：说法相同（归一化后）→ `n + 1`，情境不同就加一种写法 [M]；二元组相似度 ≥ 0.6 也合并 [A]；
- 有效权重 `= n · 0.5^(距上次出现天数 / 21) + w`：三周不说就淡一半 [A，对应 MaiBot 30 天衰减]；
- 有效权重 < 0.2 且 30 天没出现 → 删除；总数上限 120 条，超了删最弱的 [M]。

### 9.4 每轮挑什么（不调模型）

- 库里少于 5 条时不注入（还不了解对方）[M]；
- 得分 = 情境和对方这一轮的话的二元组重合 + 按有效权重加权的随机（权重映射到 1–5）[M]；最近 3 轮用过的跳过 [A]；
- **跟着关系走** [A]：好感度「一般」及以下只注入**黑话的意思**（听得懂，不模仿）；「亲近」「喜欢」挑 1–2 条说法；「暧昧」挑 3 条，并允许俏皮的；
- **跟着心情走** [A]：心情低落（愉悦度 < −0.3）时去掉俏皮的，只留温柔的；
- **反馈** [A，MaiBot 反馈评分的极简版]：上一轮注入过的说法，按 `landed` 给 `w` 加减 0.3。

注入（order 700，≤ 150 字）[M]：

```text
对方说话的小习惯（和人设不冲突时可以自然借用，不必每句都用）：
- 被夸的时候，对方会说「哼，那还用说」
- 「小狗勾」是对方撒娇时对自己的称呼
```

### 9.5 对外

服务 `companionExpression`：`version: 1`；`list()`；`forget(id)`；`teach(when, say)`（手动教一句）。接口 `GET /api/maidsh-expression/list`、`POST /api/maidsh-expression/mutate`（`edit` / `delete` / `add` / `pin`）。数据 `<DSH_HOME>/storages/maidsh-expression/expression.json`。单独装时每轮一次小调用；装了总控 0 次。

## 10. 主动面 `maidsh-initiative`（随机定时为主，0.1.0 已实现）

MaiBot 0.11 用后台随机掷骰决定主动发言（空闲越久概率越高，夜里打折），0.11.2 起移除，1.x 改为「插件往对话里插一条隐藏任务、强制跑一轮，由 TA 自己决定说不说」[M]。按你的意见，**以随机定时为主**。

### 10.1 什么时候主动开口

1. **随机定时**（主）[M 空闲掷骰 → A 预先排好的随机时刻]：每次你们聊完（以及 TA 主动之后），插件在「最早可以再主动的时刻」之后的几个小时里随机挑一个时刻，空闲越久越可能落下 [M]；落在安静时段就顺延到早上。时间到了，TA 来找你。
   - 不用 DSH 自带的定时任务：它会在对话里留一条可见的「schedule」消息，还会出现在自动化任务页。插件自己计时，到点用同样的方式（`agent.followup`）唤醒 TA，只是消息是隐藏的。
   - 手机上引擎只在 DSMO 开着时运行：到点时 App 没开，下次打开时若错过不到 2 小时，就在打开后一两分钟内补上（正好是「回来了」的感觉）；错过更久就重新排。
2. **约好的回访**：你说「我去洗澡了」「开完会找你」时，分析里填 `followup: { afterMin: 40, reason: "洗完澡" }`，到时间 TA 来问一句（同样插件自己计时）。
3. **想起一件事**：记忆里你提过的日程（明天面试、周末搬家）或拿不准想确认的事，作为上面两种时机的由头顺带问 [M 0.11 的「未回答的记忆冲突」]，不单独打扰。

### 10.2 不打扰

- 每天最多 3 次，两次至少隔 4 小时；
- 安静时段默认 23:30–08:00（可改），还会参考你平时活跃的时段自动收窄 [A，对应 MaiBot 按时段打折 M]；
- **没回就退**：TA 主动了你没回，下次要求的间隔翻倍（4 → 8 → 16 小时）；连着 2 次没回就停，直到你先开口 [M 一次性闸门 + A]；
- 好感度「冷淡」「厌恶」时不主动 [A]；
- TA 正在回复（对话进行中）时不插话，顺延 10 分钟。

### 10.3 TA 怎么开口

插件用 `agent.followup()` 往对话里放一条**隐藏的提示**（`source.kind: 'maidsh-initiative'`），跑一轮真正的回复 [M 1.x 的 proactive task]。提示里写：
- 隔了多久、当时聊到哪（「你们上次聊天是 3 小时 20 分钟前，对方说去洗澡了」），现在是什么时段 [M 停机续聊的分档：短暂离开 / 休息 / 睡了一觉 / 好久不见]；
- 现在的心情一句、关系一句；
- 记忆里的 1–2 个由头（未结的话题、对方的日程、想确认的事）；
- 要求：一两句短话、贴合人设，像自然想起对方，不提「系统」「提醒」；**没什么值得说就回 `[[skip]]`**，这一轮不显示 [M 桌宠「可以安静结束」]。

### 10.4 平时也带上时间感（零成本）

对方隔了很久才发消息时，在陪伴段落前加一句「距离上次聊天已经过去 2 天」（order 250），让回复自然带上「好久不见」的感觉 [M→A]。

### 10.5 显示和其他面

- DSMO 不显示那条隐藏提示，TA 的回复照常显示，带一个小标记「TA 先开口」[M source_kind 的思路]；
- 这一轮**不算对方说的话**：总控跳过分析（不学表达、不动好感、不写记忆）；只有你真的回了，「没回就退」的计数才清零 [A]；
- 服务 `companionInitiative`：`version: 1`；`state()`（今天主动了几次、下次最早什么时候、退避到几小时）；`pause(hours)`。

### 10.6 对约定的改动（向后兼容）

- `turnOf`（总控和各面判断「一轮结束」）跳过由 `maidsh-initiative` 发起的轮次。
- 分析里多一个 `followup` 字段（由主动面登记）。约好的回访要装总控（没有总控时只做随机主动，不为它单独调模型）。
- 判断「这一轮是谁发起的」时跳过 DSH 插进轮次里的上下文消息（带 `source.form` 的：运行时上下文、技能目录、当前时间）。
- DSMO 不显示 `source.kind` 为 `maidsh-initiative` 的消息，改为一行「TA 先开口」。

## 11. 深度学习和导入（记忆、表达；总控 0.3.0 已实现）

两种「批量学」，都由**总控**来跑（和「陪伴」页一样，装了总控才有）：

1. **深度学习一段对话**：你指定一段过去的对话，TA 把它从头到尾细读一遍，比每轮顺手记的更全；
2. **导入设定 / 大段文字**：你提供关于自己的介绍、你们的关系设定和过往、故事 / 剧情、别处的聊天记录，TA 读完记进记忆（和表达）。

### 11.1 MaiBot 怎么做的 [M]，我们改了什么 [A]

- MaiBot 的记忆导入（A_Memorix）按**文本类型**分策略切块：叙事 1600 字一块、重叠 400；设定类按语义块约 1200 字；诗和台词原文直接存、不调模型；聊天记录按整条消息切，并按参考日期把「昨天」换成具体日期。导入是后台任务，分「任务 / 文件 / 块」三层状态，失败的块可以重跑；按内容哈希跳过导入过的文件。
- MaiBot 的表达也能从文本学（单次 ≤ 20 万字，每块约 4500 字），但结果只是**候选**，要人逐条确认才入库；历史聊天没有批量回填表达的学习器。
- **MaiBot 的会话摘要导入明确排除角色扮演和剧情**，对我们的用户是个坑：我们**允许**导入剧情，虚构世界里的事单独存、和关于你本人的事分开 [A]。
- MaiBot 没有事前费用估算，也没有块级断点续传；手机上 App 随时可能被关，这两样我们都要 [A]。

### 11.2 能导入什么

| 类型 | 例子 | 进记忆的什么 | 进表达吗 |
|---|---|---|---|
| 关于我 | 自我介绍、喜好清单 | 关于你的事实，**钉住**、不淡忘 | 否 |
| 我们的过往 | 关系设定、相识经过、重要的事 | 关系设定（钉住）+ 情节 | 否 |
| 故事 / 剧情 | 你们一起写的故事、同人、剧本 | **故事世界的设定**（新种类 `world`，只在聊到时想起）+ 情节（标「故事里」） | 否 |
| 聊天记录 | 别处导出的你和 TA 的对话 | 和深度学习对话一样 | 是，只学你的话 |
| 一段过去的对话 | DSMO 里选一段 | 事实（要你的原话作证）+ 情节（用消息时间定日期） | 是，只学你的话 |

**角色设定（TA 是谁）不导入**：那是人设插件的事，DSMO 会提示你把它贴进人设。诗、歌词、台词不调模型，原文存成可引用的片段 [M]。

### 11.3 怎么跑

- **先估算再开跑**：按字数算出要切几块、调用几次模型、大约多少 token 和多久，你确认了才开始 [A]。例：10 万字 ≈ 84 块 ≈ 85 次调用 ≈ 30 万 token。
- **切块**：每块 1500 字、重叠 300 字 [M 1600/400]；聊天记录按整条消息切，不把一句话切断 [M]；单次最多 20 万字 [M]。
- **每块一次调用，记忆和表达一起出**：总控把装上的面登记的 `batch` 字段（结构和每轮分析一样，只是更全）合并成一次 [A]。一次只跑一块，不抢你聊天时的模型。
- **断点续传**：每跑完一块就存一次进度；App 被关了，下次打开从断点接着跑 [A]。同一份内容导入过会提示「已经导入过」[M]。
- **收尾**：全部块跑完后，再调一次模型，把这次新增的内容并进「我对 TA 的了解」[M 0.8 的印象压缩]。
- **可以暂停、取消、撤销**：每条导入的内容都带着这次任务的编号；「撤销这次导入」会删掉它新增的条目。和原有记忆合并过的，只撤回它加上去的那部分 [A]。

### 11.4 导入的和学来的有什么不同 [A]

- **你亲手给的优先**：导入的条目来源标 `import`，「关于我」和「我们的过往」里的事实默认钉住、不淡忘；和聊天里学到的冲突时，以导入的为准。但如果你后来在聊天里明确更正（「我已经不住杭州了」），按更正走，旧的作废、可追溯。
- **故事世界的设定**（`world`）不进常驻的「关于对方」，只在聊到相关话题时想起，不会把故事里的设定当成你本人的事。
- **从对话和聊天记录学来的表达**和每轮学的一样直接用，不用逐条确认：它们本来就是你自己的话。前 30 天不淡忘，之后同样「三周淡一半」。

### 11.5 对外

总控的接口（DSMO 以后的「陪伴」页用）：
- `POST /api/maidsh/learn`：`{ kind: 'session', sessionId }` 或 `{ kind: 'text', textType: 'aboutme' | 'backstory' | 'story' | 'chatlog', title, text }`；带 `dryRun: true` 只返回估算。
- `GET /api/maidsh/jobs`：任务列表和进度；`POST /api/maidsh/jobs`：`pause` / `resume` / `cancel` / `undo`。
- 读一段过去的对话：优先由引擎按 `sessionId` 直接读；读不到时由 DSMO 把消息传进来（DSMO 已经有导出对话的功能）。实现时核对 DSH 的接口。

面的登记新增可选的 `batch: { schema, instructions, apply(result, chunk), finish(job) }`，第三方面也可以参加批量学习。

## 12. 生效范围（总控 0.4.0）

MaiDSH 默认在**所有对话**里生效，但排除两类：
- **你关掉的对话**：每段对话的「更多」菜单里有开关（`POST /api/maidsh/scope` `{ action: "set", sessionId, enabled }`）；
- **DS Bot 的对话**：DSMO 知道哪些对话属于 Bot，启动时和 Bot 变化时把整份列表同步过来（`{ action: "set-bots", sessionIds }`），它们总是排除。

不在范围里的对话：总控不分析、不学（心情、羁绊、记忆、表达都不动），不注入陪伴段落；主动面不记它、也不会在那里主动找你。深度学习是你手动指定的，不受范围限制。
`GET /api/maidsh/scope?sessionId=…` → `{ sessionId, enabled, bot, off }`；不带 `sessionId` → `{ mode, off: [关掉的对话 id], bots: Bot 对话个数 }`。
服务 `companion` 多了 `inScope(id)`、`scopeOf(id)`、`setScope(id, enabled)`、`setBotSessions(ids)`。

范围设置在总控里：没装总控时，各面单独运行，在所有对话里生效。

## 13. 档案和生效范围（总控 0.5 起）

一句话：**每段对话归到一个「档案」或者「关」**。档案是一个陪伴对象：自己的心情、好感度、记忆、表达和主动安排。生效范围（§12）就是这件事的特例：归到「关」。

### 13.1 归属规则（越具体越优先）

| 层 | 设在哪 | 取值 |
|---|---|---|
| 1. 对话 | 对话「更多」菜单 › 陪伴 | 跟随工作区（默认）/ 某个档案 / 关 |
| 2. 工作区 | 工作区页面每一行 › 陪伴 | 跟随默认（默认）/ 某个档案 / 关 |
| 3. 默认 | 陪伴页 › 设置 | 某个档案（出厂是「默认档案」）/ 关 |
| 总是 | — | DS Bot 的对话一律「关」（DSMO 同步，§12） |

例：「默认」= 默认档案；「写《长夜》」工作区 = 「沈砚」档案；「工作」工作区 = 关；工作区里某一段闲聊单独设成默认档案。

引擎查工作区：DSH 的 `workspaceRegistry.list()` 里每个工作区带 `sessionIds`，总控按对话 id 找到工作区（缓存，工作区变化时刷新）。工作区被删、对话被移出时自动退回下一层。

### 13.2 档案里有什么

- 每个面一份独立的状态：心情、羁绊、记忆（事实、经历、印象、关键词图）、表达、主动（下次时间、回访、退避）。
- 档案自己的信息：名字、（可选）关联的人设名、创建时间、最近使用时间。
- **存储**：`<DSH_HOME>/storages/maidsh-<面>/profiles/<档案 id>/…`。现有数据原地变成「默认档案」（`default`），不搬文件。
- 最多 20 个档案；删档案时它的数据一起删（先确认，可先导出）。

### 13.3 每一轮怎么用

- 总控算出这轮对话的档案；「关」就和 §12 一样什么都不做。
- 合并分析、注入、主动都带上档案 id：`onAnalysis(result, turn)` 和 `prompt.text(turn)` 的 `turn` 多一个 `profile`；`state(profile)` 按档案给。
- 面按 `turn.profile` 读写自己那份数据。第三方的面不认识 `profile` 时照旧（它自己只有一份，所有档案共用）。
- 面之间的服务（`companionMood.get()` 等）多一个可选参数 `profile`，不给就是默认档案；羁绊读心情时用同一轮的档案。
- **主动**：每个档案各自排时间、各自记回访和退避；**每天的次数上限所有档案合计**（不会因为多几个档案就被打扰得更多）；只在属于这个档案的对话里主动。
- **深度学习和导入**：默认进「这段对话的档案」，导入设定时可以选档案。

### 13.4 和人设的关系

人设插件（dsh-persona-dafeiyu）没有给别的插件调用的接口，引擎里的总控不知道一段对话用的是哪个人设，所以「跟着人设走」放在 DSMO 这边做：

- 档案可以「关联一个人设」（只是记个名字，方便认）。
- 你在 DSMO 里给对话、工作区或全局换人设时，如果那个人设有关联的档案，DSMO 顺手把同一层的档案也切过去，并提示一句「已切到「沈砚」的档案」；没有关联就不动。
- 反过来不联动：换档案不会换人设。

这样「按人设分」和「按工作区分」都能做到，规则只有一套（13.1）。

DSMO 的做法（web/src/maidsh/profiles.ts，2026-11-21）：

- 人设库的人设是全局的，所以切的是**默认那一层**；对话、工作区两层不动。
- 档案按人设名字关联（`persona` 存名字，和总控一样 24 字以内）；没开人设记成 `（无人设）`，有自己的一份。
- 第一次（还没有档案关联过人设）：默认档案关联当前人设并改成它的名字，原来的数据整份归它；之后别的人设第一次用时新建一份。满 20 个时先共用「无人设」那份（没有就默认档案）。
- 只在一次操作做完时对一次：人设页的启用 / 关闭 / 删除 / 新建、开 App、回到前台、打开陪伴页。人设库编辑正文时会用临时名字，中途不对；人设改名时关联跟着改。
- 陪伴页的读写都带 `?profile=`（正在看的那份）；「每个人设的陪伴」列表可以看别的一份（不切换）、把一份给当前人设用、改名、删除。深度学习一段对话仍按那段对话的档案。

### 13.5 界面（等主模块做完一起做 UI 时实现）

- 陪伴页顶部：档案切换（看哪个档案的状态）、新建 / 改名 / 关联人设 / 删除；设置里选「默认」。
- 对话「更多」› 陪伴：跟随工作区 / 选档案 / 关（替换现在的开关）。
- 工作区页面每行：陪伴：跟随默认 / 选档案 / 关。

### 13.6 接口

- `GET /api/maidsh/profiles` → `[{ id, name, persona?, createdAt, usedAt }]`；`POST`：`create` / `rename` / `link-persona` / `delete`。
- `GET /api/maidsh/scope?sessionId=` → `{ sessionId, profile: id | null, from: 'conversation' | 'workspace' | 'default' | 'bot' }`；`POST`：`{ action: 'set', sessionId, profile: id | 'off' | null }`（null = 跟随上一层）、`{ action: 'set-workspace', workspaceId, profile }`、`{ action: 'set-default', profile }`、`set-bots`（同 §12）。
- 各面的列表 / 修改接口加 `?profile=`，不带就是默认档案。
- 约定升到 **v2**：`turn.profile`、`state(profile)`、服务的 `profile` 参数。总控同时接受 v1 的面（当作只有一份数据）。

### 13.7 迁移

- 装新版总控时：现有数据 = 默认档案；§12 里「关掉的对话」转成「对话 = 关」；默认 = 默认档案。用户看不到变化。
- 面的新版本先发：没有总控 0.5 时它们按默认档案工作，和现在一样。

### 13.8 实现说明

- 归属：`core/lib/scope.mjs`（存档 `scope.json` v2：`default`、`profiles`、`conversations`、`workspaces`、`bots`）。DSH 的对话只有在工作区里新建（`session/create` 带 `workspaceId`）才算进那个工作区；只给 `cwd` 的对话不属于任何工作区，走默认那一层。
- 面的写法：`shared/profiles.mjs` 的 `perProfile` 按档案懒加载实例，`profiledAspect` 把「只有一份数据」的面包成 v2（按 `turn.profile`、`chunk.profile`、`state(profile)` 分派），`dropProfile(id)` 删档案时清数据。
- 批量学习：任务带 `profile`；`batch.apply(result, chunk)` 的 `chunk.profile`、`batch.finish(job)` 的 `job.profile`、`batch.undo(jobId, profile)`。同一份材料学进不同档案不算重复。删档案会取消它没跑完的任务。
- 主动：每个档案一份 `initiative.json`，每天的次数记在 `daily.json`（所有档案共用；第一次从默认档案原来的计数接过来）。TA 主动后 `pending.sessionId` 记下是哪段对话，那段对话的回音只算给等它的档案。
- 接口上的档案（`?profile=` 或 body.profile）要是总控里存在的档案，否则 404；没装总控时只有默认档案。
- 老总控（约定 v1）不收 v2 的面：面看 `companion.version`，低于 2 就按 v1 登记（只有默认档案）。总控 0.5 照样收 v1 的面（第三方面不用改）。

## 14. 每轮注入的总预算（和设定集共用一张表）

MaiDSH 各包和设定集（`dsmo-lore`，不属于 MaiDSH，见 `LORE-DESIGN.md`）每轮加进系统提示的字数：

| 段 | 上限 | 方式 | 何时变化 |
|---|---|---|---|
| 陪伴段（总控，§3–§4） | 1000 字 | `context` `maidsh`（300） | 每轮可能变 |
| 设定集·人物名单 | 200 字 | `section` `dsmo-lore:roster`（150） | 人物增删、换作品时 |
| 设定集·此刻的设定 | 600 字（设置 `budgetChars` 300–1000） | `context` `dsmo-lore`（320） | 提到的人物 / 名词变了时 |
| 设定集·工具说明 | 约 900 字（没用作品的对话里只有 lore_start，约 80 字） | 工具 schema | 不变 |
| **合计** | **≤ 2700 字** | | 没用作品的对话约 1080 字 |

人设不算在内。超预算时整条丢、不截断。新加会注入的包要在这张表里登记自己的上限。

注意（DSH 0.2.2 核对过）：`context` 的内容一变，DSH 会在对话里追加一份完整的新快照（「This snapshot supersedes earlier runtime-context snapshots」），旧的留在历史里。所以每轮的文字要尽量稳定：同样的输入给同样的文字。

### 14.1 提示里的对话 id（总控 0.5.1）

`prompt.text(turn)` 的 `turn` 多一个 `sessionId`（这段对话）。仍是约定 v2，向后兼容。

### 14.2 记忆给设定集让位（记忆 0.3.1）

装了设定集（服务 `lore`）且这段对话用了作品时，`world` 类事实不参与回忆和常驻（不删，不用后恢复）。关于对方本人的事和经历不受影响。
