## 决定，以及落在哪

| # | 决定 | 落在哪 |
|---|---|---|
| Q1 | 换掉 dsh-Go 的原生界面，保留它的运行时和原生层；页面放进 WebView | `native/overlay/app/lib/api_demo/api_demo_home.dart` 占了「网页模式」的位置（补丁 0001），默认界面改成网页模式。原生界面还在，设置里一键切回 |
| Q2 | 只维护改动的部分；前端单独一个仓库，开源 | 3 个补丁（共十几行）+ 只新增不覆盖的 overlay 文件；`apply.sh` 检查 overlay 不覆盖任何已有文件 |
| Q2 | 用户可以自由增删改元素（如皮肤），以插件形式；市场兼容 dsh-Go 后端和我们的前端 | 一个 npm 包可以同时带 `dshGo`（dsh-Go 原生插件，引擎里跑）和 `apiDemo`（我们的前端部分）两份清单；前端同时渲染 dsh-Go 插件的胶囊、消息菜单、状态条、面板。见 [plugins.md](plugins.md) |
| Q3 | 声明式 + 沙箱网页面板；三条硬规定：授权卡、权限页、登录 / API Key 输入框不可被插件覆盖 | 皮肤只能改设计变量；布局只能隐藏白名单里的位置；面板在 `sandbox="allow-scripts"` 的 iframe 里，只能调白名单接口。三处受保护区域在封闭的 Shadow DOM 里、用固定配色，外加运行时巡检（`plugins/guard.ts`）：一旦插件样式遮住它们，立刻停用插件样式 |
| Q4 | 前端打包进 APK | `assets/api_demo/`（补丁 0003），`apply.sh` 把 `web/dist` 拷进去 |
| Q5 | JS 直连 DSH Web API；原生桥只做选文件、语音、通知、换主机、打开原生页；不支持中转主机 | 页面走本地代理直接说引擎协议（`web/src/engine/`）。桥的方法见 [bridge.md](bridge.md)。中转主机显示「这个主机用不了 DSMO」并给出切回原生界面的按钮 |
| Q6 | 混合：网页做聊天主界面和依赖对话的页面；其余打开 dsh-Go 原生页 | `web/src/ui/pages/registry.tsx` 分三处放：**聊天右上角「⋯」**（只和当前对话有关：对话详情、计划与目标、子代理、权限、产出的文件、文件、终端、后台任务、技能、引用、导出，外加 dsh-Go 插件放在 `session.tab` 的面板）；**设置**（偏好：模型、远程主机、手机操控、思考过程翻译、语音输入）；**全部功能**（其余：自动化任务、插件、插件清单、智能体团队、论坛、社区、分享配置、搜索对话、工作区）。终端、自动化任务、插件清单、智能体团队、社区类、工作区、手机操控走原生页，其余是网页 |
| Q7 | 插件拆分：引擎逻辑装在主机上，纯前端部分存在设备上 | 安装时：有 `engine` 部分的走 `pluginManager/installBundle` 装到当前主机；前端部分记在 App 的存储里（`native.storageSet('plugins')`） |
| Q8 | 第一版市场只有官方插件；写好分级审核规则和检查脚本 | `market/policy.json` 的 `officialOnly`；规则 `market/scripts/rules.mjs`，分级见 [market.md](market.md) |

### 和决定不完全一致的地方

- **终端**属于「依赖对话的页面」，按 Q6 应该是网页。第一版仍打开 dsh-Go 的原生终端（桥带上当前对话），网页终端放到下一版：它需要一个完整的终端模拟器。
- **本地代理**不在原来的计划里。读引擎源码时发现：引擎只接受它自己提供的页面（Origin 必须等于 Host，跨站请求一律拒绝），打包在 APK 里的页面没法直接连。所以 App 起一个只监听本机、带每次启动密钥的小代理，页面和引擎都把它当成同源。代理之外别的 App 用不了引擎登录。

## 前端里的几块

| 模块 | 职责 |
|---|---|
| `engine/rpc.ts` | 一次性调用：`POST /api/<endpoint>`，信封 `client-request` / `server-response` |
| `engine/mux.ts` | `/api/remote.mux` 上的多路流；每次连上先开 `$events` 等 `ready`（15 秒超时），断线后按 0.5/1/2/4/8/10 秒（50–100% 抖动）重连，旧连接上的流全部失败、由调用方重开 |
| `engine/events.ts` | 把 follow 帧、日志事件、助手流、`$events` 事件解析成类型；不认识的保留原样 |
| `engine/transcript.ts` | 把事件折叠成聊天行：按 seq 合并（重连快照幂等）、草稿被正式消息替换时保持同一行 key、授权按 callId 挂到工具行 |
| `engine/client.ts` | 各接口的类型化封装和 `watchSession`（自动重开、重连后按 resync 合并） |
| `state/store.ts` | 应用状态（Preact signals）和界面调用的动作 |
| `ui/` | 界面组件，类名和视觉沿用 chat-demo |
| `plugins/` | 我们的前端插件、dsh-Go 原生插件的渲染、沙箱面板、硬规定巡检 |
| `bridge/native.ts` | 原生桥；浏览器里每个方法都有网页版替代 |
| `mock/` | 原型用的模拟引擎（只进原型包，正式包里没有） |

## 基础模式和高级模式

| | 基础（默认） | 高级 |
|---|---|---|
| 侧边栏 | 新对话、对话列表、登录、设置 | 加上主机、插件、技能、自动化任务、手机操控、全部功能，以及插件加的入口 |
| 聊天右上角 | 无 | 「⋯」：这个对话的功能 |
| 设置 | 主题、语言、位置、高级模式、语音、账号 | 加上模型、远程主机、手机操控、思考过程翻译、完成通知 |
| 输入框 | 深度思考、智能搜索、语音、附件 | 模型 · 思考深度选择、`/` 命令和技能、`@` 引用文件、插话、待办和权限胶囊、插件胶囊 |
| 回复 | 思考过程 + 正文；工具调用只显示一行「已完成 · N 次工具调用」 | 每一步工具调用（可展开看输出），中间说的话按顺序排在步骤里 |
| 授权卡 | 一样显示（硬规定） | 一样 |

深度思考在基础模式下映射为模型的思考深度（开 = `high`，关 = `off`）。智能搜索打开时，会在消息里附一段给模型看的偏好说明（界面上不显示）。位置信息同理：打开并选了地区才附带。

## 手机布局

宽度 ≤ 767px 时（`isMobile`），`App` 渲染 `ui/mobile/MobileApp`，按 DeepSeek 安卓客户端的习惯排布；桌面仍是 chat-demo 网页风格。两套布局共用同一个 store 和引擎客户端，只有外壳不同。

- **顶栏**：左侧边栏按钮，中间对话标题，右侧自动朗读开关、⋯（仅高级模式且有对话时）、新对话。
- **侧边栏**：从左推入、把主区推开（不是盖住）；顶部搜索框进全屏搜索页；高级模式的功能入口；置顶分组；今天 / 昨天 / 7 天内 / 30 天内 / 按月分组；多选（点多选后圆点直接在每条对话左边滑出，可批量置顶、删除）；底部头像 + 设置。长按或 ··· 出菜单：重命名、置顶、多选、删除。
- **聊天**：长按自己的消息出 复制 / 选择文本 / 修改；“修改”进入输入框上方的“修改输入”状态。回复下方：复制、分叉、朗读、插件动作，右侧重新生成。修改和重新生成产生的新版本仍算同一个对话（见下面“版本与分叉”）。
- **输入框**：深度思考 / 智能搜索两个胶囊（高级模式换成模型胶囊）、+ 打开附件面板（拍照 / 相册 / 文件，对应桥的 `pickFiles` accept=camera/image/any）、空输入时是语音键（点按切换，按住说话松开发送）。
- **设置**：全屏推入的页面，分组列表（账户 / 应用 / 高级 / 语音 / 关于），字体大小、外观、语言、位置信息、个性化各自一页；登录表单仍在受保护的 Shadow DOM 里。
- **置顶**：`workspace/follow` 订阅 + `workspace/pinSession|unpinSession`。

截图脚本：`node e2e/mobile.mjs [dark|light]`，输出到 `e2e/shots/m/`。

## 导入历史对话

「数据管理 › 导入历史对话」读 DeepSeek、ChatGPT 网页导出的文件（zip 或 `conversations.json`，两者都是 `mapping` 树）、本应用导出的会话日志 JSON，以及简单的 `[{title, messages:[{role, content}]}]`。DSH 没有用旧日志建会话的接口（dsh-Go 的分享码设计里也是回放而不是续接），所以导入的对话存在这台设备上（WebView 的 IndexedDB，`web/src/history/`）：只读，边栏底部和「数据管理」里能打开；「接着聊」新建一个对话，把原对话整理成 Markdown 放进输入框，由人改完再发。同一来源同一 id 再导入会覆盖，不会重复。

## 版本与分叉

DSH 的对话日志只能追加，没有原地修改、重新回答或回退的接口，唯一的分支手段是 `session/fork`（在某个事件之后切开，新会话的日志是原会话的精确前缀，序号不变）。dsh-Go 原生界面把修改、重新回答都做成分叉并打开新对话；这里按 ChatGPT / Claude 的习惯区分两件事：

- **修改、重新生成**：仍是 `session/fork`（切在这条提问之前，`forkPointBeforePrompt`）再把提问发一次，但新会话记作原对话的一个“版本”（`web/src/state/versions.ts`，记录存在设备上）。边栏只列出当前看的那个版本；被修改的消息下（或重新生成的回复旁）出现「‹ 2 / 3 ›」切换版本。同一条消息改多次是并列的兄弟版本，不会串成一条链。删除对话会连同所有版本一起删除；置顶跟着当前版本走。
- **分叉**：回复下方的分叉按钮（切在这一轮结束处）、长按边栏里的对话（切在最近一轮结束处）、电脑上边栏对话的「⋯」菜单。分叉出来的是边栏里独立的一个新对话，标题照 dsh-Go 和官方网页端命名为「标题 (1)」「标题 (2)」…；原对话排队中的消息不会带过去。
